## 2024-05-18 - Memoizing Components without Props
**Learning:** In a large React application where a root component (like `App`) re-renders frequently, child components that receive no props and only depend on internal state or external subscriptions (like a toast notification system) will re-render unnecessarily on every parent update. Wrapping them in `React.memo` effectively isolates them, saving rendering cycles. Applying `React.memo` is highly effective on components with no props or strictly stable props (e.g., `NotificationContainer`). Avoid applying it on components with unmemoized callback props (e.g., `BottomNavBar`, `TopStatusBar`), as it renders memoization ineffective.
**Action:** Always wrap top-level generic UI containers (like notification or modal root components) in `React.memo` if they do not depend on parent props.
## 2025-02-18 - Memoizing derived state in TerminalScreen
**Learning:** Parsing log lines and sorting them into transaction objects on every keystroke was creating significant UI latency. In React, expensive derivations of frequent updates (like real-time telemetry logs and text search input) should always be wrapped in `useMemo`. When you have arrays of complex derivations passing through multiple filter steps, each step needs memoization to cut the rendering cost.
**Action:** Always wrap list parsing, formatting, and filtering inside `useMemo` when working with frequently updating state variables (like log streams) to prevent redundant work on every parent re-render.
## 2025-02-18 - Memoizing list item components on frequent parent updates
**Learning:** In terminal-like interfaces (`TerminalScreen`) where state updates frequently (like on every keystroke when typing an OBD command), unmemoized list item components (like `ResponseLineItem`) will cause massive redundant re-renders. When a long list is rendered inside a component taking text input, the individual row components must be memoized.
**Action:** Always wrap list item components that take stable props (like parsed log objects) in `memo(...)` when rendered in a parent that receives frequent, high-velocity state updates.
## 2025-02-18 - Replacing unmemoized row components with ResponseLineItem
**Learning:** In TerminalScreen, rendering a large array of log responses with inline unmemoized UI components directly inside a map function can lead to expensive redundant re-renders on high-frequency state updates like keystrokes. Replacing the inline JSX with the existing memoized ResponseLineItem component avoids these unnecessary re-renders.
**Action:** Always use the memoized list item components like ResponseLineItem rather than inline JSX inside map loops when rendering lists inside components with frequent state updates.
